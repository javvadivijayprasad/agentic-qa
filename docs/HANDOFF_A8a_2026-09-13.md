## The decision that matters: look, don't touch

The agent is admitted `browser_navigate`, `browser_snapshot`, `browser_find`, `browser_wait_for`,
`browser_take_screenshot` and the console/network readers. It is **not** admitted `click`, `type`,
`fill_form`, `press_key`, `select_option`, `hover`, `drag`, `drop`, `file_upload` or
`handle_dialog`.

So the agent can look at Juice Shop to find real selectors — which it must, because an SPA's
selectors exist only in the rendered DOM and cannot be read off disk — but the only thing that ever
*interacts* with the application is the test suite it writes, executed through `pw.run_tests`. Two
things follow. A run cannot quietly change the app's state and then assert against that state. And
the expected behaviour has to come from the acceptance criteria rather than from the agent poking
the UI until something happens, which is the difference between testing a specification and
describing an implementation.

This is only affordable because we wrote AB#1's criteria from observation. The exact string
`"Invalid email or password."` is in the story, so the agent never needs to submit a bad login to
discover it. If the run blocks because it genuinely cannot proceed without interacting, that is a
finding worth having, and we relax it deliberately rather than by default.

## What the URL check does and does not do

`matchesUrl` parses the URL and compares origin plus path, so a different scheme, host or port is
out of scope, and `http://localhost:3100@evil.com/` — where the real host is evil.com — does not
match, which a naive string prefix would have allowed. There are tests for both.

What it does not cover: **only a navigation carries a URL argument.** A link the agent follows, a
redirect, or a script-driven navigation is not re-checked by the gate. The Playwright server is
additionally launched with `--allowed-origins`, but Microsoft states plainly that this "does not
serve as a security boundary and does not affect redirects". So treat the pair as scoping against
mistakes, not as containment against a hostile page. It is written that way in the code comment and
in the config template, because a reader who assumes otherwise would be wrong in a way that matters.
